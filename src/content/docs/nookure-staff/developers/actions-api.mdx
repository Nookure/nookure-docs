The **Actions API** (`com.nookure.staff.api.action`) allows plugins and addons to:

1. **Register custom audit action types** (`ActionDefinition`) via `ActionRegistry`, including a [Tabler Icons](https://tabler.io/icons) identifier and a frontend color (`ActionColor`) that automatically synchronize with the Akko web panel.
2. **Record player, staff, and system actions** (`ActionModel`) into the database asynchronously via `ActionService`.
3. **Query paginated action history** with flexible filters and mark specific logs as protected evidence.

## Obtaining `ActionRegistry` and `ActionService`

Retrieve both services from the NookureStaff Guice `Injector` via Bukkit's `ServicesManager` (or via `@Inject` inside a NookureStaff addon):

```java
import com.google.inject.Injector;
import com.nookure.staff.api.NookureStaff;
import com.nookure.staff.api.action.service.ActionRegistry;
import com.nookure.staff.api.action.service.ActionService;
import org.bukkit.Bukkit;

NookureStaff staffApi = Bukkit.getServicesManager().load(NookureStaff.class);
if (staffApi != null) {
    Injector injector = staffApi.getInjector();
    ActionRegistry actionRegistry = injector.getInstance(ActionRegistry.class);
    ActionService actionService = injector.getInstance(ActionService.class);
}
```

## Registering Custom Actions (`ActionRegistry`)

Custom actions allow external plugins (such as Economy, Crates, Clans, or Anticheat integrations) to appear in the audit log and Akko web dashboard with their own display name, category, **Tabler Icon**, and **Color**.

### Building an `ActionDefinition`

Use `ActionDefinition.builder(id)` where `id` is a unique `UPPER_SNAKE_CASE` identifier (2–48 characters):

```java
import com.nookure.staff.api.action.model.ActionCategory;
import com.nookure.staff.api.action.model.ActionColor;
import com.nookure.staff.api.action.model.ActionDefinition;
import com.nookure.staff.api.action.model.TablerIcon;

// Using a predefined palette color and Tabler icon name
public static final ActionDefinition ECONOMY_TRANSFER = ActionDefinition.builder("ECONOMY_TRANSFER")
        .displayName("Economy Transfer")
        .category(ActionCategory.PLAYER)
        .icon("coins") // Tabler Icon: https://tabler.io/icons/icon/coins
        .color(ActionColor.AMBER)
        .build();

// Using a custom Hex color and PascalCase React icon name (normalized automatically to "gift")
public static final ActionDefinition CRATE_OPEN = ActionDefinition.builder("CRATE_OPEN")
        .displayName("Crate Opened")
        .category(ActionCategory.PLAYER)
        .icon(TablerIcon.of("IconGift"))
        .color(ActionColor.hex("#a855f7"))
        .build();
```

### Registering with `ActionRegistry`

Register your definitions during plugin startup (`onEnable`):

```java
// Register a pre-built ActionDefinition
actionRegistry.register(ECONOMY_TRANSFER);
actionRegistry.register(CRATE_OPEN);

// Or register inline using the shorthand overload
ActionDefinition anticheatFlag = actionRegistry.register(
        "ANTICHEAT_FLAG",
        "Anticheat Flag",
        ActionCategory.SYSTEM,
        "shield-exclamation",
        "#ef4444"
);
```

:::note[Automatic Frontend Synchronization]
When an `ActionDefinition` is registered:
- `ActionDefinitionRegisteredEvent` is fired on the NookureStaff `EventManager`.
- All connected Akko web clients automatically receive an `ACTION_DEFINITIONS_SYNC` (`0x19`) packet containing the registered ID, display name, category, Tabler icon, and color.
:::

### Icons (`TablerIcon`) & Colors (`ActionColor`)

- **`TablerIcon`**: Accepts any icon from [Tabler Icons](https://tabler.io/icons). Input strings are normalized to lowercase `kebab-case` (e.g., `"shield-lock"`, `"icon-shield-lock"`, `"ti-shield-lock"`, and `"IconShieldLock"` all normalize to `"shield-lock"`). Built-in constants such as `TablerIcon.SHIELD`, `TablerIcon.GAVEL`, `TablerIcon.BAN`, `TablerIcon.MESSAGE`, etc. are also available.
- **`ActionColor`**: Supports both semantic UI palette presets and arbitrary `#RRGGBB` / `#RGB` hexadecimal codes:
  - **Presets**: `ZINC`, `SLATE`, `RED`, `ROSE`, `ORANGE`, `AMBER`, `YELLOW`, `LIME`, `GREEN`, `EMERALD`, `TEAL`, `CYAN`, `SKY`, `BLUE`, `INDIGO`, `VIOLET`, `PURPLE`, `FUCHSIA`, `PINK`.
  - **Hex**: `ActionColor.hex("#ff5500")` or `ActionColor.of("#ff5500")`.

## Recording Actions (`ActionService`)

All `ActionService#record` methods execute asynchronously on a dedicated thread pool and return a `CompletableFuture<Void>`. Once persisted, `ActionRecordedEvent` is fired and broadcasted in real time to authorized Akko sessions.

### Recording a Custom `ActionDefinition`

```java
import com.nookure.staff.api.action.model.ActionLocation;
import java.util.Map;

ActionLocation location = new ActionLocation(
        player.getWorld().getName(),
        player.getLocation().getX(),
        player.getLocation().getY(),
        player.getLocation().getZ()
);

Map<String, Object> metadata = Map.of(
        "amount", 5000,
        "currency", "Coins",
        "reason", "Shop purchase"
);

// Record action with actor, optional target, definition, location, and metadata map
actionService.record(actorModel, targetModel, ECONOMY_TRANSFER, location, metadata);

// Simple overload without target, location, or metadata
actionService.record(actorModel, CRATE_OPEN);
```

### Recording a Built-In `ActionType`

You can also record any built-in `ActionType` enum constant directly:

```java
import com.nookure.staff.api.action.model.ActionType;

actionService.record(staffModel, targetModel, ActionType.STAFF_TELEPORT, location, null);
```

## Querying Actions & Marking Evidence

### Querying by `ActionDefinition` or `actionTypeId`

```java
import com.nookure.staff.api.action.model.ActionModel;
import io.ebean.PagedList;

// Find paginated actions for a specific ActionDefinition (page 1, 20 items per page)
PagedList<ActionModel> crateLogs = actionService.findByDefinition(CRATE_OPEN, 1, 20);

for (ActionModel log : crateLogs.getList()) {
    String typeId = log.getActionTypeId(); // e.g., "CRATE_OPEN"
    Map<String, Object> meta = log.getMetadata();
}

// Flexible filtering across actor, target, actionTypeId, category, serverName, and date range
PagedList<ActionModel> filtered = actionService.findActionsByTypeId(
        actorModel,
        null,
        null,
        null,
        "ECONOMY_TRANSFER",
        ActionCategory.PLAYER,
        "survival-1",
        null,
        null,
        1,
        25
);
```

### Protecting an Action as Evidence

Actions marked as evidence (`isEvidence = true`) are protected from automatic database purges (`purgeOlderThan`):

```java
actionService.setEvidence(actionId, true).thenAccept(updated -> {
    if (updated) {
        logger.info("Action #" + actionId + " is now locked as protected evidence.");
    }
});
```
